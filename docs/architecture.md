# 需求与架构

目标是“阅读 → 三色标记 → 截图 → 筛选 → pending → 受限放行 → Anki → 同步”，不是截图全部变卡。Agent 可 ACCEPT、DEFER、REJECT，用户不用逐词审批；程序限制与证据门不能被模型绕过。

## 架构选择

比较过云编排 + Mac 执行桥与本地 SQLite + Mac worker。选择本地方案，复习历史与写入控制集中在 Mac，减少外传与部署成本。代价是 Mac 离线只能暂存，移动端离线不能实时执行全局上限。

B：Share Sheet → Shortcut，最初使用 iCloud 文件交付，沿用现有截图保存/剪贴板/分享思路。C：直接向同一固定目录放入图片。HTTP 收件代码已实现，但私有网络/HTTPS 传输未部署，不能在 iPad 上使用 Mac 的 127.0.0.1。相册是独立适配器，尚未实现，不声称文件监听等于相册监听。

## 状态与职责

Python 管 ID、SHA、schema、持久化、分数计算、预算、Anki 最小差异和审计。Apple Vision 管本地 OCR。Agent 只给词汇语义判断。Anki 管 SRS 和原生同步。

- 收件：received → awaiting_analyzer / analyzed / error。
- 候选：pending / deferred / rejected → reserved → written；已有同义项追加出处为 enriched。
- 写入：reserved → writing → written → sync_requested；异常为 write_uncertain。
- `sync_requested` 不表示媒体或移动端已收到。

Minimal 字段为词形、lemma、词性、标记、原句、当前义、sense_label、决策/理由、证据引用、不确定项和排序分项。Extended 提供版本化通用词频、可授权的分级/学术来源、少量搭配。System 数据为哈希、稳定身份、映射、状态、时间戳、预留、真实首次作答和日志。

v0.1 词频在模型调用前作为证据提供；CEFR/AWL 尚未置备，填 null。学术分没有明确证据时验证拒绝。用户/Anki 历史的完整语义融合仍在后续阶段，不能用缺失历史认定成熟。生成释义是推断，不是假词典引用。

## 预算不变量

正常核心新词 20–30，硬上限 35；超过 30 需要满足轻负荷特殊日。允许 0 新词恢复日。初版卡预算最多 30/特殊日35，附加 Context 最多5。核心和卡独立计数。

每个维度：当天已首学 + 已放行未确认首学 + 新预留 ≤ 当日额度。SQLite BEGIN IMMEDIATE 防止最后一个额度被并发领取两次。未学预留跨日保留。人工改排程日志不计首次学习，使用最早真实回答事件。

当前学习日政策通过显式 `day` 命令输入，要求新鲜历史及移动端交接标记。它是受控开发接口；自动验证全天复习用时、延迟抽测、其他牌组库存、同步交接尚未实现。不可把这个账本称为自动学习计划调度完成。

## Note / Card

EntryID 是规范 lemma 的稳定摘要。Recognition 固定主考点，Context1/2 以条件模板生成。字段 HTML 转义，不加载脚本。`UserNotes` 保留人工内容；其他字段出现外部编辑时停止写入。

`make_plan` 按既有 sense label 稳定映射。模型描述同义项有漂移的风险，需要真实样本测试及后续受控 sense 选择；目前不能认为字符串匹配已经解决语义去重。既有不受管 Note 的导入/迁移尚未实现，必须先审阅库存并补映射，不能开启写入后指望系统自行猜。

## 阶段

1. 本地输入与测试资料库闭环（v0.1）。
2. 用户真实样本颜色/释义校准、选定分析服务与授权数据源。
3. 正式 Anki 只读库存、旧模型映射、首学历史、学习日自动政策。
4. 低额度真实运行，移动端同步与7个学习日验收。
5. 相册适配、语义去重强化、必要迁移与扩容。

当前不迁移旧资料库、不生成音频/反向卡、不抓整本教材、不复制所有派生或同义词。
